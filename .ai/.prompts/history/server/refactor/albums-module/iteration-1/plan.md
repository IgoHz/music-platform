# plan

## Goal

Analyze the requested feature and produce a practical implementation plan.

## Instructions

- Follow the engineering philosophy defined in AGENTS.md.
- Apply all relevant skills automatically.
- Reuse existing repository patterns whenever possible.
- Inspect the current repository before producing the plan.
- Do not begin implementation.

Produce:

## Understanding

Summarize:

- requested functionality;
- constraints;
- assumptions;
- success criteria.

## Repository Analysis

Summarize:

- relevant architecture;
- affected modules;
- reusable patterns;
- existing conventions;
- dependencies that influence the implementation.

## Risks

Identify:

- implementation risks;
- dependency concerns;
- migration considerations;
- edge cases;
- architectural inconsistencies (if any).

## Implementation Plan

Break the work into small, sequential implementation steps.

Each step should:

- have a clear objective;
- produce a reviewable change;
- build on previous steps;
- avoid mixing unrelated responsibilities.

Prefer:

- incremental delivery;
- vertical feature slices over technical-layer phases.

## Validation Strategy

Describe how implementation should be verified.

If architectural inconsistencies or ambiguities are discovered, explain them separately from the implementation plan.
